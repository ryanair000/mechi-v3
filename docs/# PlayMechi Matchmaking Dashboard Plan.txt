# PlayMechi Matchmaking Dashboard Plan

## 1. Product Direction

PlayMechi should be built as a dashboard-first matchmaking platform.

The public website should explain the product, market the brand, and bring users into the dashboard. The dashboard should be where all player activity happens.

## Core Principle

Public pages explain PlayMechi.
The dashboard runs PlayMechi.

## Public Pages

Public pages should support the product but should not contain the main player activity.

Recommended public pages:

```txt
mechi.club/
mechi.club/home
mechi.club/how-it-works
mechi.club/pricing
mechi.club/tournaments
mechi.club/support
mechi.club/download
```

# 2. Main Product Positioning

## Short Positioning

PlayMechi is the competitive gaming dashboard for African gamers.

## Main Headline

Challenge players. Find matches. Climb the ranks.

## Supporting Message

PlayMechi helps gamers create challenges, find opponents, join tournaments, submit results, track stats, climb leaderboards, and build a verified competitive gaming profile.

## What PlayMechi Is Not

PlayMechi should not feel like only a tournament flyer website.

It should not feel like a gambling app.

It should not depend on cash-stake matches at launch.

It should not start with custom Ludo yet.

## What PlayMechi Should Be First

PlayMechi should first become:

```txt
A player dashboard
+ challenge board
+ match room system
+ result confirmation system
+ ranking system
+ tournament support system
+ subscription platform
```

# 3. Dashboard-First Architecture

The dashboard should be the product.

A player should log in and immediately understand:

```txt
What can I play now?
Who challenged me?
Which match is active?
Which result do I need to submit?
What tournament am I in?
What is my rank?
What plan am I on?
What should I do next?
```

## Dashboard Home Purpose

The dashboard home should not be a landing page.

It should be a command center.

## Dashboard Home Priority

The order of importance should be:

1. Play now
2. Active match
3. Pending actions
4. Open challenges
5. Rank progress
6. Joined tournaments
7. Rewards
8. Subscription status
9. Announcements
10. Streams/social content

The current Weekend Cup-style hero card can remain, but it should not dominate the dashboard. It should become a smaller featured event card.

# 6. UI Design Direction

## Design Goal

The UI should feel like a real gaming operations dashboard, not an AI-generated landing page.

It should be:

```txt
Dark
Fast
Sharp
Clean
Functional
Status-driven
Action-first
```

It should not be:

```txt
Over-glossy
Over-gradient
Over-animated
Full of fake cards
Full of stock images
Full of random glowing sections
Generic SaaS-looking
```

## Visual Style

Use the existing PlayMechi identity:

```txt
Dark navy background
Teal accent
Red/coral accent
White text
Soft borders
Subtle shadows
Gaming-style icons
Rounded cards
Compact tables
Status badges
```

## Suggested Color System

```txt
Background:
#07111F or similar dark navy

Surface:
#0E1A2D
#111D31

Border:
#22334D

Primary Accent:
Teal / cyan

Danger Accent:
Coral / red

Text:
White for primary
Light gray for secondary
Muted gray for helper text

Status:
Green = confirmed / active
Yellow = pending
Red = disputed / failed
Blue = info
Purple = Pro / Elite highlight
```

## UI Rule

Use color to communicate status, not decoration.

Every color should have a job.

## Typography

Use one strong display font for headings and one clean UI font for everything else.

Recommended approach:

```txt
Headings: bold, compact, gaming feel
Body: clean, readable, simple
Buttons: short and direct
Labels: uppercase only when useful
```

Avoid too many font weights.

## Spacing

Use consistent spacing.

Recommended spacing scale:

```txt
4px
8px
12px
16px
24px
32px
48px
```

Do not randomly space cards.

## Cards

Every card should have one clear purpose.

Good card:

```txt
Active Match
eFootball 1v1 vs Brian254
Awaiting result · Deadline 8:45 PM
[Open Match Room]
```

Bad card:

```txt
Compete with the best players and unlock endless opportunities in the next generation of gaming excellence.
```

Cards should be scannable and actionable.

# 7. Anti-AI-Slop UI Rules

## What To Avoid

Avoid these common AI-generated UI problems:

```txt
Huge generic hero sections inside dashboard
Random glassmorphism
Too many gradients
Fake analytics numbers
Fake users
Fake testimonials
Stock images everywhere
Cards with vague titles
Buttons that do not lead anywhere
Too much marketing copy inside logged-in areas
Overuse of emojis
Overuse of glowing borders
Random 3D icons
Inconsistent icon styles
Too many shadows
Too much vertical space
Repeated card patterns with no real data
```

## Dashboard Copy Rules

Use short functional copy.

Good:

```txt
Submit result
Accept challenge
Find match
Check in
Upload proof
Confirm score
Open match room
```

Bad:

```txt
Embark on your competitive journey and unlock your gaming destiny.
```

## Data Rules

Never show fake stats as if they are real.

If there is no data, show a useful empty state.

Bad:

```txt
1,293 active players
```

when the platform has no real activity.

Good:

```txt
No open challenges yet.
Create the first challenge for eFootball.
[Create Challenge]
```

## Empty State Rules

Every empty state should include:

```txt
What happened
Why it matters
What the user can do next
```

Example:

```txt
No active match
You are not currently playing anyone.
Join the queue or create a challenge to start competing.

[Join Queue] [Create Challenge]
```

## Button Rules

Use one main button per card.

Examples:

```txt
Find Match
Create Challenge
Open Match Room
Submit Result
Confirm Result
Upgrade to Pro
```

Avoid five equal buttons in one card.

## Icon Rules

Use one icon family.

Do not mix:

```txt
Lucide icons
Font Awesome icons
Random emoji icons
3D icons
AI-generated icons
```

Pick one and stay consistent.

Recommended:

```txt
Lucide icons
```

## Image Rules

Use images only where they help.

Inside the dashboard, images should be secondary.

Use images for:

```txt
Featured tournament
Community post
Stream announcement
Game cover
```

Do not use images for:

```txt
Every card
Every stat
Every action
Every empty state
```

## Animation Rules

Use subtle animation only.

Allowed:

```txt
Hover lift
Button loading spinner
Toast slide-in
Modal fade
Queue searching pulse
```

Avoid:

```txt
Constant glowing
Floating cards
Overanimated gradients
Random particle backgrounds
Spinning icons
```

# 11. Matchmaking System

## Matchmaking Types

PlayMechi should support two types of matchmaking.

### Queue Matchmaking

The player says:

```txt
Find me an opponent now.
```

Flow:

```txt
Player goes to /dashboard/play
Selects game
Selects platform
Selects casual or ranked
Clicks Find Match
System searches for opponent
Both players accept
Match room is created
Players play outside PlayMechi
Result is submitted
Opponent confirms
Rating updates
```

### Challenge Board

The player says:

```txt
I want to create a challenge and wait for someone to accept.
```

Flow:

```txt
Player goes to /dashboard/challenges
Clicks Create Challenge
Selects game, mode, platform, rank range, time
Challenge appears on open board
Another player accepts
Match room is created
Players play
Result is submitted and confirmed
Ranking updates
```

## Matchmaking Filters

Use:

```txt
Game
Platform
Region
Rank
Availability
Trust score
Match history
No-show rate
Subscription level where applicable
```

## Early MVP Matching Rules

```txt
Match similar ranks first
Widen rank range after waiting
Avoid players with recent disputes against each other
Avoid high no-show users
Allow rematch after completion
```

# 14. Result Submission

Because matches happen outside PlayMechi, result verification is critical.

## Result Modes

### Mutual Confirmation

Best for normal 1v1 matches.

Flow:

```txt
Winner submits score
Opponent confirms
Match finalizes
Rating updates
```

### Screenshot Proof

Best for ranked matches and tournaments.

Require:

```txt
Score screenshot
Opponent name if visible
Match time
Game ID or lobby ID where possible
```

### Moderator Review

Used when players disagree.

Moderator reviews:

```txt
Scores
Screenshots
Match history
Comments
User trust score
No-show history
```

## Result Statuses

```txt
Not submitted
Submitted
Confirmed
Auto-confirmed
Disputed
Rejected
Finalized
```

## Auto-Confirmation Rule

If a player submits a result and the opponent does not respond within a set time, the result can auto-confirm unless disputed.

Suggested window:

```txt
Casual match: 30 minutes
Ranked match: 60 minutes
Tournament match: admin-defined
```

# 17. Subscription Strategy

PlayMechi should offer daily, weekly, and monthly options.

Daily and weekly options are important because many players may not want to commit to monthly billing immediately.

## Subscription Naming

Use simple names:

```txt
Free
Pro Daily
Pro Weekly
Pro Monthly
Elite Daily
Elite Weekly
Elite Monthly
```

Alternatively, call daily/weekly products “passes”:

```txt
Pro Day Pass
Pro Weekly Pass
Pro Monthly
Elite Day Pass
Elite Weekly Pass
Elite Monthly
```

This may be clearer because daily and weekly access can be bought as one-time access first before full recurring billing.

## Recommended Pricing

### Free

```txt
KES 0
```

### Pro

```txt
Pro Daily: KES 20/day
Pro Weekly: KES 70/week
Pro Monthly: KES 199/month
```

### Elite

```txt
Elite Daily: KES 50/day
Elite Weekly: KES 199/week
Elite Monthly: KES 699/month
```

## Why These Prices Work

The daily pass lowers the barrier.

The weekly pass is good for players who only compete during weekends.

The monthly plan gives the best value and should be the main plan.

## Pricing Psychology

Make monthly look like the best deal.

Example:

```txt
Pro Daily: KES 20
Pro Weekly: KES 70
Pro Monthly: KES 199
```

A player who buys Pro Daily many times will realize monthly is better.

Example:

```txt
Elite Daily: KES 50
Elite Weekly: KES 199
Elite Monthly: KES 699
```

Elite monthly should be positioned for hosts and serious players.

# 20. Subscription Implementation

## Recommended Billing Logic

Use two types of access:

### One-Time Passes

Good for:

```txt
Daily Pro
Weekly Pro
Daily Elite
Weekly Elite
```

These can be sold like access passes.

A user pays once and gets access until expiry.

### Recurring Subscription

Good for:

```txt
Pro Monthly
Elite Monthly
```

Monthly subscriptions can be recurring where payment provider support allows it.

## Subscription Statuses

```txt
Free
Trial
Active
Expiring Soon
Expired
Cancelled
Payment Failed
Grace Period
```

## Access Rules

When a player buys a pass or subscription:

```txt
Set plan_level
Set plan_started_at
Set plan_expires_at
Unlock plan features
Show plan badge
Track renewal or expiry
```

## Expiry Rules

When plan expires:

```txt
Return user to Free
Keep match history but lock advanced history view
Keep badge in history but remove active badge
Disable Pro/Elite-only actions
Show renew CTA
```

## Plan Upgrade Rules

If user upgrades before expiry:

```txt
Apply higher plan immediately
Extend expiry fairly if possible
Show confirmation
```

## Plan Downgrade Rules

If user downgrades:

```txt
Let current paid access continue until expiry
Apply lower plan after expiry
Do not delete user data
Only lock access to premium views
```

# 26. Codex Implementation Approach

Codex should not be asked to “make the dashboard beautiful” in one vague prompt.

That leads to AI slop.

Codex should be given small, structured engineering tasks with clear UI rules, file targets, acceptance criteria, and screenshots or existing design references.

## Codex Working Method

Use this process:

```txt
1. Create a product spec
2. Create a design system spec
3. Create database schema
4. Create route map
5. Create component list
6. Build components first
7. Build pages from components
8. Add real empty states
9. Add loading/error states
10. Test flows
11. Review UI manually
12. Refactor
```

## Codex Should Work in Phases

Do not ask Codex to generate everything at once.

Use phases:

```txt
Phase 1: Design system
Phase 2: Dashboard shell
Phase 3: Player profile and game IDs
Phase 4: Challenge board
Phase 5: Match room
Phase 6: Result submission
Phase 7: Rankings and leaderboard
Phase 8: Subscriptions
Phase 9: Admin dashboard
Phase 10: QA and cleanup
```

## Codex Prompting Rule

Every Codex task should include:

```txt
Goal
Files to edit
Files not to edit
UI style rules
Data requirements
States required
Acceptance criteria
Testing instructions
```

## Bad Codex Prompt

```txt
Build me a modern gaming dashboard with matchmaking and subscriptions.
```

This is too vague and will likely create generic AI UI.

## Good Codex Prompt

```txt
Build the /dashboard/play page using the existing PlayMechi dashboard shell.

Requirements:
- Keep the current dark navy PlayMechi style.
- Do not create a giant marketing hero.
- Use compact action-first cards.
- Add a Play Now card with game, platform, mode, match type, and Find Match button.
- Add an empty state for no active queue.
- Add loading, error, and success states.
- Use existing Button, Card, Badge, Select, and Tabs components.
- Do not introduce new colors outside the design tokens.
- Do not add stock images.
- Do not use fake player counts.
- Make the page responsive.
- Add basic tests if the project has test setup.

Acceptance criteria:
- User can select a game.
- User can select ranked or casual.
- User can click Find Match.
- Empty state appears when no queue is active.
- UI matches existing dashboard spacing and typography.
```

# 34. Final Recommendation

Build PlayMechi as a dashboard-first matchmaking platform.

The dashboard should contain all player activity.

Public pages should only support the dashboard.

Start with:

```txt
Player profiles
Game IDs
Challenge board
Match rooms
Result confirmation
Ranking
Subscriptions
Admin moderation
```

Do not start with custom Ludo yet.

Do not start with risky cash-stake matches yet.

Start with structure, trust, match history, ranking, and community activity.

The strongest PlayMechi path is:

```txt
Dashboard-first matchmaking
→ Challenge board
→ Match rooms
→ Rankings
→ Daily/weekly/monthly Pro access
→ Elite host tools
→ Tournaments
→ Custom games later
```

The dashboard should make every player ask:

```txt
Who can I play now?
What match do I have?
What rank am I?
What result do I need to submit?
What tournament am I joining?
What can I unlock next?
```

That is the product.
